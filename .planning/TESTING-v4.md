# Ручное тестирование крафта и станков

Прогон на живом сервере для критериев готовности `SPEC-v4.md` §1. Как сделано на самом деле —
`SPEC-v4.md` §15, и ожидания ниже написаны по нему, а не по §3–§13.

Автотесты (`TransformTest`, `PreviewSlotTest`, `StorageTest`, `MechanismTest`) проверяют группировку
и хранение, но ни один не поднимает событие сервера. Связка «клик → транзакция» проверяется только
здесь.

---

## 0. Прочитать до начала

Запуск, права, команды, фильтры и чтение ответа `/pp verify` — как в `TESTING-v3.md` §0. Ниже только
то, что нужно этой фазе сверх того.

### Где видны строки

Чтение по-прежнему только по позиции (`SPEC-v4.md` §15.3). Поэтому:

- **Станки** — наковальня, точило, кузнечный стол, камнерез, ткацкий станок, картография, стол
  зачарований, печь и варочная стойка — пишут свои слоты на позицию блока. `/pp lookup`, глядя на
  станок, показывает расход из его слотов **и** подтягивает остальные проводки той же транзакции,
  включая результат на курсоре игрока.
- **Верстак и сетка 2×2** записаны на игрока. Командой их не увидеть: проверяются через сверку
  (`/pp reconcile`) и счётчик `INFERRED`.

Фильтр `action:transform` оставляет только причины трансформации: `craft_*`, `smelt`, `brew`,
`anvil_combine`, `grindstone`, `smithing_*`, `enchant_apply`, `stonecutter`, `loom`, `cartography`,
`book_sign`.

### Счётчик `INFERRED` — только на выключении

Строка `movements the capture could not explain: <причина>=<число> ...` пишется в лог **раз в сутки
и на выключении**, а после записи счётчик обнуляется. Командой его не вызвать. Значит, каждый раздел,
где проверяется критерий 2, кончается командой `stop`. После неё строку ищут в логе. Если
необъяснённого не было, строки нет вовсе: это и есть ожидаемый ответ.

### Дисциплина прогона

1. Всё в **выживании**. Креатив подменяет клики своими действиями (`creative_set`), и строки перестают
   значить то же самое. Исключение одно: пункт C6.
2. Свежий мир на прогон. Ресурсы выдать себе заранее, до первого кейса, и перезапустить сервер: так
   выдача не попадёт в счётчик раздела.
3. После каждого кейса — `/pp lookup` по станку, если он есть, затем `/pp verify recent` и
   `/pp reconcile`.
4. Не пересобирать плагин и не запускать `./gradlew test`, пока сервер работает: подменяется jar.

## B. Станки

Для каждого: `/pp lookup` по станку показывает расход из его слотов и результат на курсоре одной
транзакцией с причиной станка. Слот результата строк не пишет.

### B1. Наковальня

- [ ] Ремонт: инструмент + материал (алмазная кирка + алмаз)
- [ ] Переименование: только предмет, без второго слота — одна строка расхода и одна строка результата
- [ ] Книга зачарований на меч

### B2. Точило

- [ ] Два повреждённых инструмента одного типа в один
- [ ] Снять чары с зачарованного предмета

### B3. Кузнечный стол

- [ ] Алмазная кирка → незеритовая: причина `smithing_transform`
- [ ] Отделка брони: причина `smithing_trim`

### B4. Камнерез

- [ ] Один камень → ступенька (один выход)
- [ ] Шифт-клик по результату со стеком камня: причина `stonecutter`, количество совпадает с тем, что
      пришло в инвентарь

### B5. Ткацкий станок

- [ ] Знамя + краситель → знамя с узором: причина `loom`

### B6. Картография

- [ ] Увеличить карту бумагой, затем заблокировать стеклянной панелью: обе — `cartography`

### B7. Стол зачарований

- [ ] Зачаровать книгу с расходом лазурита
- [ ] `/pp lookup` по столу: предмет и лазурит уходят под `enchant_apply`, зачарованный приходит под
      `enchant_apply`. Отдельной `enchant_lapis_consume` нет, так сделано сознательно (§G)

### B8. Подпись книги

- [ ] Подписать книгу с пером в руке
- [ ] Строку командой не увидеть (книга у игрока). Проверка — `/pp reconcile` и отсутствие
      `book_sign` в счётчике раздела E

### C4. Сетка 2×2 в инвентаре

- [ ] Скрафтить доски из бревна в инвентаре, не открывая верстак

### C5. Сверка при открытой сетке

- [ ] Положить предметы в сетку верстака и, **не закрывая окно**, выполнить `/pp reconcile <ник>` с

- [ ] Этот пункт в счётчик раздела E не включать: креатив делать после `stop` раздела E

## G. Что работать **не** должно — не считать багом

| Наблюдение | Почему |
| --- | --- |
| Крафт на верстаке не виден в `/pp lookup` | Чтение только по позиции, а сетка записана на игрока (`SPEC-v4.md` §15.3) |
| Лазурит уходит под `enchant_apply`, а не `enchant_lapis_consume` | Одна причина на трансформацию (`SPEC-v4.md` §15.2) |
| Пустое ведро после торта — `craft_result` | Остаток приходит из `Void` так же, как результат (§15.2) |
| Возврат сетки при закрытии — `container_remove` | Отдельной метки нет, движение записано верно (§15.2) |
| Покраска, копия книги, знамени и карты — `craft_*` | Это рецепты верстака (`SPEC-v4.md` §4.2) |
| Износ инструмента не пишет строк | Решено `SPEC-v4.md` §7 |
