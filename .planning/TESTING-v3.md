# Ручное тестирование блочной плоскости

Прогон на живом сервере. Всё, что ниже, проверяется руками: автотесты закрывают кодеки, хранилище и
чистые решения, но ни один из них не поднимает событие сервера, поэтому связка «событие → строка»
проверена только здесь.

---

## 0. Прочитать до начала — чем смотреть

Обе плоскости читаются одной командой. `/pp lookup` и инспектор показывают предметные проводки и
блочные строки вместе, в порядке того, как всё происходило, новое сверху.

Строка предметной проводки:

```
2026-08-18 14:02:11  blk_tnt  -1 minecraft:stone  slot 0  to nowhere  by Alice
```

Строка блочная:

```
2026-08-18 14:02:11  blk_tnt  minecraft:stone -> minecraft:air  block 10 64 -3  by Alice (worked out)
```

Читать так:

- `(worked out)` — имя выведено лестницей, а не увидено. Прямое событие такой пометки не несёт.
- `by nobody named` — виновника не нашли. Строка всё равно записана: ненайденный виновник не повод
  не записывать исчезновение.
- `+contents` — у строки есть сохранённая нагрузка блок-сущности (текст таблички, содержимое).
- `-> ` показывает обе стороны. Строки с одной стороной не бывает, писатель её не принимает.

Кроме команд смотреть в лог:

| Что | Строка в логе |
| --- | --- |
| Расхождение плоскостей | `plane gap in ...` |
| Позиции, отдавшие больше, чем брали | `... gave up more than the item plane ever booked to them` |
| Покрытие сверки | `planes compared to the end of the item plane, ...` |
| Непокрытые пути | `movements the capture could not explain: ...` |
| Инвариант транзакции | `ledger gap: ...` |

### Запуск

```
./gradlew runServer
```

Сборка Canvas 26.2, билд 923. Себе выдать права:

```
/op <ник>
```

Даёт `pfauprotect.lookup`, `pfauprotect.inspect`, `pfauprotect.reconcile` (все `default: OP`).

### Команды

```
/pp lookup                     — журнал блока, на который смотришь (до 6 блоков)
/pp lookup user:<ник> time:2h radius:10 limit:50
/pp near [радиус]              — журнал вокруг себя, по умолчанию радиус 5
/pp inspect on | off           — щёлкать по блокам и читать их журнал
/pp reconcile [<ник>]          — сверка того, что игрок несёт, с журналом
/pp verify                     — прогнать обе самопроверки прямо сейчас
/pp verify recent              — то же, но судить и позиции моложе минуты
```

Псевдонимы: `l`, `n`, `i`, `r`, `v`. Полное имя команды — `/pfauprotect`.

`near` считает от того места, где стоишь, а не от блока, на который смотришь: это то, чем пользуются,
когда рядом только что что-то произошло и указывать уже не на что.

Фильтры по блочным причинам:

```
action:block        — вся блочная плоскость
action:+block       — установка игроком
action:-block       — слом игроком
action:explosion    — динамит, крипер, кровать, якорь, кристалл
action:fire         — сгорание и распространение огня
action:liquid       — разрушение жидкостью и образование из неё
action:piston       — выдвижение и втягивание
action:gravity      — отрыв и приземление
action:nature       — рост, костная мука, распад, увядание, образование, скалк
action:mob          — эндермен, иссушитель, разрушитель, серебрянка, снеговик, ледоход, мелкая порча
action:dispenser    — установка раздатчиком
action:portal       — создание и разрушение портала
```

`include:` и `exclude:` работают и по блокам: `include:stone` покажет строки, у которых любая из
двух сторон — камень.

### Расписания и окна — сколько ждать

| Что | Период |
| --- | --- |
| Свёртка предметного журнала | 5 мин |
| Сверка плоскостей | 10 мин |
| Сверка с натурой по всем игрокам | 30 мин |
| Полный проход по заметкам атрибуции | 5 мин |
| Отчёт о непокрытых путях | раз в сутки и на выключении |

| Окно | Длительность |
| --- | --- |
| Позиция не судится сверкой, пока свежее | 60 с |
| Заметка об установке (цепочки воды и огня) | 30 с |
| Заметка об удалении (кто убрал опору) | 100 мс |
| Полёт под id сущности | 60 с |
| Заявка на перечитывание позиции | 50 мс |

**Ждать эти расписания не нужно: `/pp verify` прогоняет обе проверки сразу и до конца.** Ответ
приходит в чат, а не только в лог. Расписания оставлены в таблице, потому что на живом сервере
проверки идут сами и их строки в логе всё равно надо уметь читать.

**Позиция моложе минуты сверкой не судится** — плоскости пишутся двумя потоками, и сразу после
действия они на мгновение расходятся сами с собой. Поэтому сразу после кейса брать `/pp verify
recent`: он отдаёт это окно и судит свежее. Ценой изредка попадающейся гонки, которую надо
перепроверить обычным `verify` через минуту.

Читать ответ так:

```
Transaction invariant: 1482 entries, 0 gaps, 0 unreadable.
Two planes: 63 positions compared, 0 gaps, 0 overdrawn, 209 the block plane never recorded,
0 too recent to judge, 0 unreadable.
```

`gaps` и `overdrawn` — нули, всё остальное информационное. `never recorded` растёт нормально: это
позиции, о которых блочная плоскость ничего не знает. `unreadable` обязан быть нулём всегда.

### Что в логе значит «плохо»

- `plane gap in ... at X Y Z` — позиция потеряла блок, а предметная плоскость его всё ещё держит.
  Это ровно тот долг, ради которого всё делалось; на покрытых путях его быть не должно.
- `... gave up more than the item plane ever booked to them` — обратная неисправность: списали
  оттуда, куда не начисляли. Ждать её на природных блоках (их никто не ставил) — норма; на
  поставленных руками — нет.
- `... could not be compared by this build` — строку не удалось прочитать. Никогда не должно быть.
- `ledger gap: ...` — у движения потерялась половина. Никогда не должно быть.
- `registry ... has handed out N of its M numbers` — предупреждение о заполнении словаря. На тесте
  не должно появляться.

### Дисциплина прогона

1. Свежий мир на каждый крупный раздел, иначе долги предыдущего раздела читаются как новые.
2. Каждый кейс начинать с **установки блока руками** — иначе позиции нечего терять и половина
   проверок вырождается.
3. После действия: `/pp lookup` по позиции, затем `/pp verify recent`.
4. Лог держать открытым всё время, а не смотреть в конце.

## A. Старт, жизненный цикл, удаление мира

### A1. Первый старт

Запустить на пустой папке данных.

- [ ] В логе одна строка вида `ledger open, N world bases, registry sizes: item_type=… world=… player=… block_state=…`
- [ ] `block_state=0` — словарь состояний наполняется лениво, обходом реестра на старте не занимается
- [ ] Ни одного предупреждения о заполнении словаря
- [ ] Старт не заметно медленнее, чем без плагина
- [ ] Появилась папка `plugins/PfauProtect/ledger` и `plugins/PfauProtect/blocks/<uuid>` по одной на мир

### A2. Ленивая выдача номеров состояний

- [ ] Поставить и сломать десяток разных блоков
- [ ] Перезапустить, в стартовой строке `block_state` вырос и примерно равен числу разных состояний,
      которых коснулись, а не двадцати восьми тысячам

### A3. Перезапуск

- [ ] Остановить `/stop`, в логе нет `SEVERE`
- [ ] Запустить снова, база открылась, `block_state` и `item_type` не обнулились
- [ ] `/pp lookup` по позиции, тронутой до перезапуска, отдаёт ту же историю

### A4. Загрузка и выгрузка мира

- [ ] Создать второй мир (`/mv create` или любой аналог), в логе при следующем старте на одну базу больше
- [ ] Выгрузить мир — сервер не падает, в логе нет `SEVERE`
- [ ] Поставить блок в момент сразу после выгрузки — сервер не падает

### A5. Удаление мира — это удаление директории

- [ ] Создать мир, застроить, сломать, дать сверке пройти
- [ ] Остановить сервер
- [ ] Удалить папку мира **и** `plugins/PfauProtect/blocks/<uuid-этого-мира>`
- [ ] Запустить: журнал открывается, свёртка проходит, в логе нет ни `SEVERE`, ни нечитаемых строк
- [ ] `/pp lookup` по оставшимся мирам работает
- [ ] В `registry sizes` номер мира израсходован ровно один на удалённый мир (не растёт заново)

### A6. Выключение под нагрузкой

- [ ] Ломать блоки и в этот момент выполнить `/stop`
- [ ] В логе нет `the ledger lost entries while shutting down`
- [ ] Нет `SEVERE` о незакрытой базе
- [ ] Запустить снова — база открывается, LOCK-файл не держится

## B. Установка и слом игроком

Покрытый путь. Здесь всё должно быть идеально; если тут расходится, дальше смотреть бессмысленно.

### B1. Простая установка и слом

- [ ] Поставить камень. `/pp lookup` по позиции: проводка `BLOCK_PLACE`, `+1`
- [ ] Сломать его. Проводка `BLOCK_DROP`, `−1`, и рождение дропа
- [ ] Сумма по позиции — ноль
- [ ] `/pp verify recent` не находит расхождений

### B2. Затопленный блок

- [ ] Поставить лестницу (stairs) под водой, сломать
- [ ] Баланс позиции ноль, `plane gap` нет
- [ ] блочная строка говорит `oak_stairs[...] → water[level=0]`, а не `→ air`

### B3. Ламинария и морская трава

- [ ] Сломать ламинарию/морскую траву под водой
- [ ] `plane gap` нет
- [ ] после стороны — вода, а не воздух (это тот случай, где поиск по строке
      `waterlogged=true` ошибся бы)

### B4. Лёд

Правило переписано с самого блока, у него четыре условия.

- [ ] Лёд на камне, сломать киркой без «шёлкового касания» → на месте вода
- [ ] Лёд над воздухом, сломать → на месте воздух
- [ ] Лёд, сломанный киркой с «шёлковым касанием» → лёд падает предметом, на месте воздух
- [ ] Лёд в творческом режиме → воздух (творческий слом ничего не роняет, значит и не тает)
- [ ] Плотный лёд (packed ice) и синий лёд → всегда воздух, они не тают
- [ ] Ни в одном из случаев нет `plane gap`
- [ ] после стороны совпадает с тем, что реально стоит

### B5. Отказ сервера после события — командный блок

- [ ] Оператором поставить командный блок
- [ ] Зайти игроком в творческом режиме **без прав оператора**, ударить по командному блоку
- [ ] Блок остаётся стоять
- [ ] `/pp lookup` по позиции: **новой проводки о сломе нет**
- [ ] `plane gap` не появляется

### B6. Отказ сервера до события — меч в творческом

- [ ] В творческом режиме взять меч, щёлкать левой кнопкой по чужой постройке
- [ ] Ничего не ломается
- [ ] Ни одной новой проводки
- [ ] Заметки атрибуции не пишутся: сразу после этого рвануть динамит рядом (см. E), виновником не
      должен оказаться щёлкавший

### B7. Защита спавна

- [ ] `spawn-protection=16` в `server.properties`
- [ ] Не-оператором встать снаружи защищённого квадрата и щёлкнуть по грани блока, ведущей внутрь
- [ ] Блок откатывается сервером
- [ ] **Проводки об установке нет**

### B8. Двойные блоки

Каждый — дважды: ломать верх, потом низ.

- [ ] Дверь
- [ ] Кровать
- [ ] Подсолнух / высокая трава
- [ ] Выдвинутый поршень (ломать голову)

Для каждого:
- [ ] Баланс позиции обеих половин сходится
- [ ] `/pp verify recent`: расхождений нет **ни по одной из двух позиций**
- [ ] обе позиции получили строку под одним идентификатором события

### B9. Двойной сундук

- [ ] Поставить двойной сундук, сломать одну половину
- [ ] Оставшаяся половина стоит и работает
- [ ] `plane gap` по ней не появляется
- [ ] у уцелевшей половины есть строка `chest[type=right] → chest[type=single]`

### B10. Нагрузка блок-сущности — табличка

- [ ] Поставить табличку, написать текст с форматированием (цвет, светящийся)
- [ ] Сломать
- [ ] у строки есть нагрузка «до», и она полная, а не отображаемый текст
- [ ] Пока читателя нет: убедиться хотя бы, что слом таблички не даёт `plane gap`

### B11. Именованный шалкер

- [ ] Назвать шалкер на наковальне, положить внутрь предметы, поставить, сломать
- [ ] Дроп сохраняет имя
- [ ] `/pp lookup`: позиция отдала обратно **именованный** шалкер, а не голый
- [ ] Баланс сходится

### B12. Цветочный горшок и торт со свечой

Блоки, у которых нет своей предметной формы, но позиция была оплачена.

- [ ] Поставить цветочный горшок с цветком, сломать
- [ ] Поставить торт, воткнуть свечу, сломать
- [ ] Баланс позиции сходится, `plane gap` нет
- [ ] Проверить, что не появилось `gave up more than the item plane ever booked to them`

## C. Разрушение не игроком

### C1. Динамит

- [ ] Поставить руками десяток блоков, положить рядом динамит, поджечь
- [ ] `/pp lookup` по любой из разрушенных позиций: проводка с причиной `BLK_TNT`, `−1`
- [ ] Баланс каждой поставленной руками позиции — ноль
- [ ] `/pp verify recent`: расхождений нет **ни по одной**
- [ ] Природные блоки в радиусе взрыва дадут `gave up more...` — это ожидаемо, их никто не начислял

### C2. Крипер

- [ ] Заманить крипера на постройку из поставленных руками блоков
- [ ] Причина `BLK_CREEPER`
- [ ] Баланс сходится

### C3. Кровать и якорь возрождения

- [ ] В Нижнем мире поставить кровать на постройку, щёлкнуть
- [ ] Причина `BLK_BED_EXPLOSION`, виновник — щёлкнувший
- [ ] То же с якорем возрождения в Верхнем мире: `BLK_RESPAWN_ANCHOR`
- [ ] Позиция самой кровати (обе половины) обнулилась

### C4. Огонь

- [ ] Построить деревянную постройку из поставленных руками блоков
- [ ] Поджечь кресалом
- [ ] Причина `BLK_FIRE_BURN` у сгоревших
- [ ] Баланс сгоревших позиций — ноль
- [ ] `plane gap` нет

### C5. Вода, которая разрушает

- [ ] Поставить руками факелы/редстоун/траву
- [ ] Пустить на них воду
- [ ] Причина `BLK_LIQUID_DESTROY`, баланс обнулился

### C6. Вода, которая **не** разрушает — самая важная проверка этого раздела

- [ ] Поставить руками дорожку из камня
- [ ] Пустить воду **поверх** неё, так чтобы вода текла по камню, ничего не ломая
- [ ] `/pp lookup` по камню: **ни одной новой проводки**
- [ ] Баланс каждого камня остался `+1`
- [ ] `plane gap` нет
- [ ] В отчёте `movements the capture could not explain` не появилось всплеска

Если здесь появятся фантомные списания — это ровно та ошибка, ради которой делалась проверка
жидкости по правилу самого сервера.

### C7. Лава и обсидиан

- [ ] Свести воду и лаву, получить обсидиан/булыжник
- [ ] Причина `BLK_LIQUID_FORM`
- [ ] Позиция, где стояла жидкость, не даёт `gave up more...`

### C8. Эндермен

- [ ] Дать эндермену унести поставленный руками блок
- [ ] Причина `BLK_ENDERMAN`, баланс обнулился

### C9. Иссушитель

- [ ] Призвать иссушителя рядом с постройкой
- [ ] Причина `BLK_WITHER` — **и от ближнего боя, и от черепов**
- [ ] Не должно быть половины инцидента под `BLK_EXPLOSION`

### C10. Разрушитель, серебрянка, снеговик, ледоход

- [ ] Разрушитель ломает листву/лозу: `BLK_RAVAGER`
- [ ] Серебрянка входит в камень: `BLK_SILVERFISH`
- [ ] Снеговик оставляет снежный след: `BLK_SNOWMAN`
- [ ] Сапоги с ледоходом по воде: `BLK_FROST_WALKER`

### C11. Мобы, ломающие по мелочи

- [ ] Житель-фермер собирает урожай, кролик ест морковь: `BLK_MOB_GRIEF`

### C12. Рост, увядание, распад

- [ ] Саженец вырастает сам: `BLK_GROW`, **одна** запись, не две
- [ ] Костная мука из руки на саженец: `BLK_BONEMEAL`, **одна** запись
- [ ] Костная мука из раздатчика на саженец: `BLK_BONEMEAL`, **одна** запись
- [ ] Листва распадается после слома ствола: `BLK_LEAF_DECAY`
- [ ] Снег и лёд тают: `BLK_FADE`
- [ ] Лёд намерзает на воду: `BLK_FORM`
- [ ] Скалк расползается: `BLK_SCULK`

**Двойная эмиссия — главное здесь.** Если у одной позиции появились две строки на одно изменение,
цепочка состояний порвана и вся атрибуция ниже по течению врёт. Проверять по числу проводок в
`/pp lookup`, а не на глаз.

### C13. Отмена костной муки только на закрывающем событии

Требует плагина, отменяющего `BlockFertilizeEvent` и не трогающего `StructureGrowEvent`. Если такого
под рукой нет, пункт пропустить и записать как непроверенный.

- [ ] Дерево не вырастает
- [ ] Строк в журнале нет

### C14. Кактус и тростник

- [ ] Поставить кактус/тростник на песок, убрать песок из-под него
- [ ] Верхние сегменты осыпаются
- [ ] Их позиции обнуляются, `plane gap` не появляется

Это отдельный путь: эти блоки снимают себя из отложенного тика, а не из обновления формы.

### C15. Навесное, потерявшее опору

- [ ] Поставить руками факел на стену, сломать стену
- [ ] Факел падает предметом
- [ ] Баланс позиции факела — ноль
- [ ] Виновником назван тот, кто убрал стену, и пометка — «выведено», не «факт»

### C16. Предсказание не пишется как факт

- [ ] Поставить факел на блок, ударить блок **не до конца** (отменить добычу)
- [ ] Факел стоит
- [ ] **Ни одной проводки о сломе факела**
- [ ] Баланс факела остался `+1`

## E. Атрибуция

### E1. Динамит, поставленный одним и подожжённый другим

Ключевой сценарий фазы. Лестница отвечает фактом, пока факт есть, и выводом только когда факта нет:
поджигателя сервер записывает сам, а установщика приходится доставать из журнала.

- [ ] Игрок A ставит динамит
- [ ] Игрок B поджигает кресалом
- [ ] В проводках о разрушенных блоках виновник — **B** (тот, кто поджёг), без пометки «выведено»
- [ ] Повторить с огненным шаром вместо кресала — результат тот же
- [ ] Подорвать динамит A редстоуном, чтобы человека-поджигателя не было вовсе: виновник — **A**
      (тот, кто поставил), пометка «выведено»

### E2. Динамит, поставленный и выкопанный

Проверка того, что лестница умеет отвечать «не знаю».

- [ ] Игрок A ставит динамит в позицию P
- [ ] Игрок A выкапывает его обратно
- [ ] Игрок B ставит **другой** динамит в ту же позицию P и подрывает
- [ ] Виновник — **B**, ни в коем случае не A

### E3. Динамит с задержкой

Журнальная ступень нужна там, где заметки в памяти уже нет и поджигателя-человека тоже нет.

- [ ] A ставит динамит, ждёт больше минуты (заметка в памяти протухла)
- [ ] Подорвать редстоуном, а не рукой
- [ ] Виновник всё равно **A**, пометка «выведено» — сработала журнальная ступень

### E4. Крипер, подожжённый кресалом

- [ ] Поджечь крипера кресалом (не бить!)
- [ ] Виновник разрушений — поджёгший
- [ ] Повторить огненным шаром — результат тот же

### E5. Цепочка воды

- [ ] Вылить ведро воды, дать ей протечь пять-шесть блоков и разрушить что-то поставленное руками
- [ ] Виновник — вылививший, хотя окно заметки короче, чем шла вода

### E6. Цепочка огня

- [ ] Поджечь угол деревянной постройки, дать огню разойтись
- [ ] Виновник сгоревших блоков вдалеке — поджёгший

### E7. Кто убрал опору

- [ ] Столб песка, под ним блок
- [ ] Игрок A убирает блок под столбом
- [ ] Песок падает, виновником назван A, пометка «выведено»

### E8. Двое рядом

- [ ] A ломает блок **прямо под** столбом песка
- [ ] B в тот же тик ломает блок по диагонали, ничего не держащий
- [ ] Виновником должен выйти **A** — грани проверяются раньше диагоналей

Повторить пять-шесть раз: раньше выигрывал тот, кто попал раньше в порядке перебора.

### E9. Полёт

- [ ] Песок падает и приземляется в другом месте
- [ ] Виновник у обеих строк один
- [ ] Форма приехала вместе с блоком: сломать приземлившийся песок, баланс исходной и конечной
      позиции сходится

### E10. Полёт, не кончившийся приземлением

- [ ] Песок падает в пустоту (сломать пол над бездной)
- [ ] Исходная позиция списана, баланс ноль
- [ ] `plane gap` по исходной позиции нет

### E11. Выгрузка чанка во время полёта

- [ ] Уронить песок в далёком чанке, немедленно уйти так, чтобы чанк выгрузился
- [ ] Вернуться, дать песку приземлиться
- [ ] Баланс сходится, **не** появляется двойного списания и не появляется `gave up more...`

### E12. Поршень никого не обвиняет

- [ ] Построить редстоун-часы с поршнем, оставить работать
- [ ] Виновник в поршневых проводках **пуст**
- [ ] Игрок, собравший часы, не назван виновником сдвигов
